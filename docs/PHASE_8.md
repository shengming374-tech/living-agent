# 阶段 8：日常、日记、睡眠与梦境隔离 / Phase 8: Daily Life, Diary, Sleep, and Dream Isolation

## 已实现

- 私人项目：创建、查看、按乐观版本更新状态和内容。
- 每日计划：按日期保存类型化项目，状态变化会自动开始或结束活动记录。
- 活动日志：记录开始、完成、失败或取消状态，以及可选证据 ID。
- 日记：按日期保存草稿或已发布版本，并验证活动、记忆和梦境来源。
- 睡眠周期：按配置时区扫描当天活动、安全 `ThoughtRecord`、已提交现实记忆和待审查候选。
- 记忆巩固报告：列出待审查候选和按相同主题聚合的重复记忆簇，不自动提交、修改、合并或删除记忆。
- 梦境记录：固定保存为 `factuality="dream"` 和 `reality_eligible=false`。
- 自我修改提案：Agent 只能暂存人格或普通提示词变更并运行现有测试；所有者批准后才部署。
- 夜间调度器：默认关闭；启用后按 IANA 时区和指定小时运行前一天的睡眠周期。
- 控制台：`/studio#life` 提供项目、计划、活动、日记、睡眠、梦境和提案管理。

全部生活 API 使用 `/v1/life` 前缀，并要求配置的所有者身份。生产环境还必须通过管理 Bearer 认证。

## 隔离边界

睡眠周期只读取已经存在的记录并生成独立汇总。每次运行都把 `automatic_memory_writes` 固定为 `0`。梦境 ID 不是 `TrustedEvent` ID，不能用作候选记忆的可信来源；即使有人手工提交梦境内容，现有记忆防火墙也会保留 `dream` 事实性，现实召回会排除它。

日记生成只使用可观察活动标题、安全想法摘要和已提交现实记忆 ID，不保存隐藏思维链。日期已有日记时，睡眠周期不覆盖所有者编辑的内容，也不追加梦境来源。

自我修改提案始终以 `living-agent` 为提案者。提案创建会生成差异、运行 Persona/Prompt 的现有回归测试并保留暂存版本，但不会写入部署文件。普通成员和 Agent 自己不能批准或拒绝。基础版本过期时，提案会变为 `superseded`。`host/root.txt` 不接受此流程，仍必须使用带所有者二次认证、恢复点和重启生效语义的专用根提示词流程。

## 配置

```yaml
life_timezone: Asia/Shanghai
life_nightly_enabled: false
life_nightly_hour: 3
life_scheduler_poll_seconds: 60.0
```

启用夜间调度前应确认部署时区。手动和定时触发使用同一个按日期唯一的睡眠周期；已完成日期再次触发会返回原记录，不会创建第二个梦境。

## 恢复行为

启动时会把仍处于 `running` 的睡眠周期标记为 `failed`，错误码为 `startup_interrupted`，不会猜测崩溃前是否完成，也不会重放记忆写入。调度器不会自动重试任何已有日期，包括失败记录；所有者可以检查活动、日记和审计后再决定后续处理。

## 已测试

最终阶段验证结果：完整 Python 测试 `200 passed`；Ruff 全部通过；严格 mypy 检查 `126` 个源文件通过；OpenClaw 桥接回归 `13 passed`；控制台与桥接 JavaScript 语法检查通过。

- 非所有者无法读取生活数据或提案。
- 项目和计划使用版本冲突保护。
- 计划项目状态转换会产生一条活动轨迹。
- 日记拒绝不存在的来源 ID。
- 同日期睡眠周期幂等，调度器同一天只运行一次。
- 睡眠巩固前后长期记忆不变，自动记忆写入为零。
- 梦境固定为非现实事实，且梦境 ID 不能冒充可信事件来源。
- 重启恢复会把中断睡眠周期标记失败。
- Agent 提案在所有者批准前不改文件；Agent 和普通成员不能批准。
- 根提示词提案被拒绝，过期提案变为已失效。

## 当前限制

- 日常计划由所有者或宿主控制面创建，尚无基于模型的自动日程规划器。
- 自我修改提案服务已实现，但当前没有自主生成补丁内容的模型触发器；控制面只能让所有者提交待测试内容，记录仍固定标明 Agent 提案并禁止 Agent 审批。
- 日记和梦境使用确定性、规则化文本生成，不调用 LLM。
- 重复记忆只按规范化主题提出簇，不做语义合并。
- 夜间调度使用进程内任务与数据库唯一日期约束，不是多实例分布式租约。
- 没有物理睡眠、生物体验或真实意识声明。
- 0.2.0 已提供图片输入和文本回答；语音、视频、附件以及图片输出仍延后到后续版本。
