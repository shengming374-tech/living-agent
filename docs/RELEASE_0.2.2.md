# 0.2.2：自动记忆与平台可靠性 / Automatic Memory and Platform Reliability

0.2.2 修复长期记忆默认不产出的问题，并补齐 NapCat 入站幂等与 OpenClaw 群聊合同。版本不引入开放式 LLM 记忆抽取，继续使用有界、可审计的确定性规则。

## 自动记忆闭环

- 默认启用自动候选生成与受限自动审批，部署方仍可分别关闭两个开关。
- 支持一条消息提取多项资料、关系、偏好、固定安排和长期计划。
- 支持第一人称“请记住”请求，例如“请记住我每周三晚上上课”。
- 候选 ID 由来源事件、类别、顺序和内容稳定派生，同一事件重放不会重复写入。
- 新候选复用现有来源、范围、事实性、敏感内容和冲突防火墙；手工候选与 Agent 自发候选不自动提交。
- 私聊记忆保持用户私人范围，群聊记忆保持会话范围；已提交记忆可在下一轮进入 `RETRIEVED_MEMORY` 上下文。
- 未认证输入、问句、疑似注入、权限、凭据、联系方式和命令型内容不会自动进入记忆。

## 平台修复

- NapCat 使用数据库保存 `(self_id, message_id)` 与事件指纹，覆盖并发重放、重启后重放、处理中断和消息 ID 冲突。
- 新增 `0012_napcat_idempotency` 迁移，旧数据库在启动升级后获得持久幂等表。
- OpenClaw 请求、回复授权和投递回执都携带群聊标记，并使用独立群聊会话范围。
- OpenClaw 桥接转发可用的提及信号；缺少正式提及信号时安全降级为未提及，不扩大自动回复。

## 配置变化

```yaml
memory_auto_candidates_enabled: true
memory_auto_approval_enabled: true
```

若要完全关闭自动记忆，需要同时将两个开关设为 `false`。若只关闭自动审批，候选仍会进入所有者审查队列。
