# LivingAgent 交付计划

## 架构目标

LivingAgent 是围绕单个对外数字人格构建的独立运行时。社交认知负责是否参与和如何表达；执行认知只返回结构化任务证据，不能发送用户可见文本。任何外部影响都必须经过代码强制的能力代理。

每个已实现阶段都必须在阶段提交前通过 pytest、Ruff 和 mypy。后续阶段的模式只在可执行切片需要时加入，避免占位模块。

当前阶段 5 切片从近期可信发言计算十分钟的 `ConversationMomentum`，区分新会话、来回对话和连续用户消息。发言判断让确认性消息保持简短，同时允许短问题或继续展开的想法使用少量短消息单元。私聊和明确点名保持响应；可选的未点名群聊参与使用连续用户发言阈值、距上次 Agent 发言的冷却时间和基于稳定事件摘要的可配置参与率，只产生一条短反应，且疑似指令不能触发。频率计算最多读取 128 条持久化发言，模型上下文仍只保留最近 8 条。

`UtteranceSession.sent_count` 和状态只有在传输层确认投递时才推进。近期会话历史来自已投递单元，而不是完整生成计划。Session 计划、单元、代次、来源事件和进度均持久化；启动时按平台/会话恢复最新进行中 Session，但不自动重发。共享协调器持有每个平台/会话的代次：新输入会取消活动 Session、唤醒后续延迟、压制迟到的旧模型输出，并通过 `utterance.replanned` 审计记录关联新的 Session。延迟使用配置区间中点；测试通过 Settings 禁用等待。

经过认证的社交事件会按稳定平台身份自动注册用户，保存展示名、首次/最近出现时间、消息计数和最近会话。注册发生在信任标准化后且不保存权限。仅所有者的读取 API 可查看资料；未认证和非社交来源被排除。

平台兼容切片：NapCat OneBot 11 反向 WebSocket 作为宿主持有的适配器实现，提供认证入口和绑定同一事件的代理回复。它能顺序投递 `UtteranceSession` 中的短单元。同一会话收到新消息时，会取消尚未开始发送的单元，并在审计中记录开始、投递和未发送数量。入站 `message_id` 与内容指纹持久化，精确重放、并发重放和重启后重放都不会再次进入运行时，复用 ID 的不同内容会失败关闭。

OpenClaw 微信兼容层使用类型化 `before_dispatch` 合成回复合同。它认证并划分入口命名空间、应用通道/账户白名单、代理绑定同一事件的回复，并在失败时关闭，不把人格或权限交给 OpenClaw。同一会话的新消息会取消未发送的后续单元并压制迟到旧结果；服务端还拒绝被中断 Session 的迟到投递回执。LivingAgent 重启后，经过认证、范围正确且顺序一致的回执仍可完成当前 Session；重复回执保持幂等。私聊和群聊文本、提及信号及持久化入站重放键已实现；媒体和主动消息仍是后续工作。

嵌入提供方已接入长期记忆：确定性 Mock、OpenAI 兼容提供方、严格传输/响应验证、仅所有者 API、持久向量迁移、启动回填、版本同步和混合召回。范围过滤和现实事实性过滤始终先于语义排序；自动索引带来源污染标签经过能力代理，失败时降级到词法召回。默认启用的保守规则从认证社交自述和第一人称明确记忆请求创建并自动审批候选，支持一条消息提取多项资料、关系、偏好和计划，同一事件重放保持幂等；所有候选仍经过来源、范围、敏感内容和冲突防火墙。等价候选会去重，冲突候选保持待审；所有者可手动替换并让旧节点进入带版本的 `superseded` 软删除状态，也可通过单步手动记忆端点完成创建和提交。控制台支持所有者批准或拒绝候选；可选自发记忆按稳定低频采样从已投递的普通 Agent 回复生成 `self/inferred` 会话候选，并强制进入人工审批。开放式 LLM 抽取和 PostgreSQL `pgvector` 加速仍是后续内容。

云端聊天兼容层使用 OpenAI 兼容、非流式 Chat Completions，保留根策略/数据上下文分离，验证有界最终文本，隔离提供方失败，并只记录安全操作元数据。真实部署依赖所有者提供端点、模型 ID 和凭据。

阶段 6 是持久化类型化任务内核。确定性任务理解生成有界计算、报告、工作区文件、公网页面/搜索、每日计划和确认式 argv 进程动作；每个步骤包含一个 CapabilityRequest、依赖集合、重试上限、结果和证据。执行器支持多次插件或宿主工具调用，在失败后停止依赖步骤，只重试瞬时进程失败，独立验证完成状态，支持重启恢复，并且没有重新取得所有者确认时绝不恢复被中断写入或进程启动。文件、网页、搜索和进程输出按不可信工具数据处理，不能增加计划步骤。所有者 API 提供任务状态、报告、确认和取消；聊天支持确认、查看和取消。只有社交认知能表达结构化结果，命令解释器、删除、环境秘密、第三方发送和开放式模型动作规划仍不在动作目录内。

阶段 7 是与 FastAPI 同源并内置发布的管理控制台。它操作现有记忆、人格、提示词、插件、任务、用户、审计和版本 API，增加只读能力清单/撤销和只读行为模拟器。模拟器走真实的信任、动量、发言判断和有界执行提案路径，但不持久化事件/任务/审计，不调用模型/插件，也不产生外部影响。控制台不能创建能力授权。

阶段 8 加入仅限所有者的私人项目、每日计划、活动、日记、睡眠周期、梦境和 Agent 自我修改提案。睡眠周期只汇总已存在的现实记忆、候选、活动和安全想法摘要，自动记忆写入固定为零。梦境固定为非现实事实，不能作为可信事件来源。Agent 只能暂存并测试人格或普通提示词修改，所有者批准后才部署；根提示词仍走专用二次认证流程。夜间调度默认关闭，并按日期保持幂等。

0.2.1 在阶段 5 的发言 Session 之上加入 MaiBot 式社交运行时。每个会话先进入持久化调度状态，由回复必要性评分决定 `trigger/wait/delay/suppress`，再进入原有 `observe/react/engage/act` 表达层。会话焦点、冷却、强制唤醒和连续空转次数可恢复；直接私聊和明确点名可以触发，普通群聊仍受阈值、冷却和稳定参与率限制。运行时还保存带来源、会过期的 `SessionImpression`，并只在当前消息与近期线索相关且场景不严肃时生成一次性 `AttentionCue`。这些派生状态会进入类型化上下文，但不是事实记忆，不能授权工具、跨会话访问或支持“我记得”的声明。新消息会使旧规划代次失效，迟到模型结果在可见表达前被丢弃。

0.2.2 关闭了长期记忆“配置存在但默认不产出”的缺口：经过认证的明确自述和第一人称记忆请求默认生成候选，经同一防火墙自动审批后可在下一轮按范围召回；单条消息支持多事实，同一事件重放保持幂等。NapCat 入站键和指纹改为数据库持久化，OpenClaw 桥接补齐群聊、提及、范围和投递回执合同。

0.2.3 让执行认知可以完成宿主明确声明的工作：所有者可在聊天中列出、读取、搜索和写入工作区 UTF-8 文本，读取公网网页、执行可配置网页搜索，并创建、追加、查看或更新每日计划。所有动作都进入持久化任务内核；文件和计划写入必须逐次确认，重启后不会自动重放。文件与网络边界拒绝目录逃逸、敏感凭据、私网目标和不受限响应，工具内容始终作为不可信数据进入模型。版本仍不开放 Shell、进程、删除、环境秘密或第三方发送。

0.2.4 把 `admin_ids` 作为显式受信任工作身份：所有者和管理员可以通过确定性自然语言目录提出工作，管理员的写入和进程请求仍只能由所有者确认。默认开启的 Shell 切片执行精确 argv，不调用命令解释器；命令名、cwd、参数、超时和输出都有边界，进程组按 TERM/KILL 回收并留下退出证据。任务聊天命令补齐状态查询和取消。自动记忆对等价事实去重、对冲突事实保留人工审查，手动替换保留旧节点版本和来源。

## 最小可用垂直切片

1. 经过认证的适配器提交带平台身份的消息。
2. 信任边界创建 `TrustedEvent`，在代码中分配权限，并把消息内容标记为外部数据。
3. 发言判断生成结构化 `TurnDecision`。
4. 上下文编译器分别标记策略、所有者请求、社交聊天、不可信数据、任务、记忆和能力，不抹平其信任语义。
5. 模型提供方可提出文本或结构化动作，但不能授予权限。
6. 能力代理验证身份、会话、模式、范围、污染、写入意图、确认、跨会话访问和外部发送。
7. 运行时或子进程插件只执行已经允许的授权。
8. 验证器生成结构化证据；社交认知以同一个人格表达一条短反应或少量短语义单元。
9. 安全裁决和实际影响写入插件代码无法访问的只追加应用审计服务。

## 本轮交付标准

### 阶段 0

- 固定版本的机制研究和来源记录，不借用源代码。
- 明确独立运行时与许可证边界。
- ADR、威胁模型、工程假设、打包、Lint、类型和测试基线。

### 阶段 1

- 由迁移后 SQLite 支持的 FastAPI 健康检查和聊天端点。
- 可信事件、权限、污染传播、审计日志、能力裁决、上下文编译器、事件总线和确定性 Mock 模型。
- 覆盖冒充、不可信指令、未授权写入、审计、迁移、健康检查和聊天的测试。

### 阶段 2

- 严格的清单和请求/结果模式。
- 插件发现、每次调用一个子进程、标准输入输出 JSON-RPC、最小环境、超时、终止和崩溃隔离。
- 计算任务合同经过能力代理，得到验证结果，再由社交认知表达。

## 后续里程碑

阶段 3 在允许长期召回声明前加入保留来源的记忆防火墙和管理/版本 API。阶段 4 加入持久安全想法摘要、心理状态衰减、未解决话题、任务活动和连续性证据约束。阶段 5 加入可中断、有节奏、可重规划的发言。阶段 6 加入持久化类型化任务规划、执行恢复和证据验证。阶段 7 在持久化与安全合同成熟后加入所有者控制面。

阶段 8 已按严格事实隔离和所有者批准语义完成。0.2.0 已落地图片输入和文本回答；0.2.1 已落地社交调度、焦点、中期印象和有来源注意力联想；0.2.2 已补齐默认自动记忆闭环和平台可靠性合同；0.2.3 已补齐有证据、可确认、可恢复的受控工作能力；0.2.4 已补齐可信管理员、确认式 Shell、自然语言任务控制和冲突记忆生命周期。现有媒体段占位符仍不代表已理解音频、视频或附件。
