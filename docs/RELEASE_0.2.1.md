# 0.2.1：社交运行时

0.2.1 的目标是借鉴 MaiBot 已验证的社交运行机制，让 LivingAgent 更自然地决定何时参与、关注哪个会话、如何处理中断，以及一段对话结束后留下什么近期印象。它不是工作型 Agent 版本，也不扩展工具目录。

## 已实现

- 会话输入先进入持久化 `ConversationRuntimeState`，再由 `ReplyNecessityEvaluator` 产生 `trigger`、`wait`、`delay` 或 `suppress`。
- 待处理事件最多保留 32 个，直接私聊和明确点名可强制唤醒；群聊继续使用连续发言阈值、稳定参与率和冷却。
- 会话焦点、冷却、强制唤醒和连续空转次数持久化；新的触发会把旧焦点降级，连续空转达到阈值后退出焦点。
- 新消息可以使旧的模型规划失效。规划代次在可见表达前再次检查，迟到结果只写入受限审计，不产生消息、记忆使用或新的表达 Session。
- `SessionImpression` 保存带来源、有限有效期的近期会话印象。达到事件阈值后优先请求结构化摘要，解析失败时使用确定性摘要；印象不是事实记忆，不能授予权限。
- `AttentionCue` 只允许由近期印象和当前事件的可追溯线索产生，一次使用后失效；严肃情绪、明确求助和问句会抑制联想。
- 上下文新增 `SESSION_IMPRESSION` 与 `ATTENTION_CUE` 区段，保留来源和污染标签，不把派生状态插入根策略。
- 行为模拟器现在预览调度结果；仿生评估覆盖调度、焦点、联想来源、严肃场景抑制和过期规划丢弃。
- 中文人格路径的固定任务反馈、连续性阻止和模型失败提示已与默认 Persona 语言一致。

## MaiBot 机制边界

本版本借鉴的是回复必要性、消息积累、Focus、idle backoff、中期记忆、注意力联想和可中断规划这些机制思想。没有导入或运行 MaiBot 源代码，也没有复制其数据表、类名、插件接口或运行时。

## 配置

```yaml
social_scheduler_enabled: true
social_focus_idle_exit_cycles: 3
social_mid_term_min_events: 6
social_mid_term_ttl_hours: 72.0
social_attention_cue_ttl_minutes: 30.0
```

`social_scheduler_enabled=false` 只关闭新增调度层，不会关闭原有信任边界、发言门控、中断投递和权限检查。主动向外发送消息、随机自言自语、开放式长期记忆抽取和新的工作工具仍未实现。

## 恢复与安全

新增三张表由 `0011_social_runtime` 创建。会话状态、印象和联想都可以从数据库恢复；模型摘要失败不会阻断普通聊天。任何印象或联想都不能成为记忆声明、权限授予或跨会话访问的依据。

## 验证

本版本应通过完整 pytest、Ruff、mypy 和迁移测试。新增行为测试验证群聊消息积累、跨会话焦点切换、中期印象上下文、严肃场景联想抑制和迟到模型结果丢弃。
