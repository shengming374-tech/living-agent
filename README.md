# LivingAgent

[中文](README.md) | [English](README.en.md)

LivingAgent 是一个从零设计的持续数字人格运行时，目标是同时具备自然的社交参与和可靠、受策略约束的任务执行能力。项目不声称具有真实意识，也不会虚构生物身体或现实人生经历。

当前基础能力包括可信输入、受权限代理约束的执行、保留来源的长期记忆、受管理的人格与提示词版本、可持久化的心理状态证据、多步骤执行内核、0.2.0 图片输入理解、0.2.1 的会话调度与中期社交记忆、0.2.2 的自动记忆闭环、0.2.3 的受控工作区/网页/每日计划、0.2.4 的可信用户自然语言工作、确认式 Shell 和完整任务/记忆生命周期、0.2.5 的事实/叙事双层长期记忆、隔离探针和召回证据链，以及 0.2.6 的可安装运行资产、NapCat 有界排队、模型瞬时故障恢复和控制台认证门控。语音、视频、通用附件解析和第三方业务连接器仍属于后续功能，具体状态列在下文。随项目提供的管理控制台通过同一个 FastAPI 服务开放现有管理流程。

## 人格社交 + 自主目标 Agent

0.3.0 新增有持久状态的 **观察 → 决策 → 工具执行 → 反馈** 循环。模型根据真实结果选择下一步，沿用人格、心理状态和有范围的记忆；原有固定任务命令继续可用。

启动后打开 `/studio#agent`，或在聊天中发送 `agent: 检查工作区并读取 README`。默认 Mock 可跑通这个真实文件演示；开放式目标使用已配置的 `openai_compatible` 模型。工作区由 `LIVING_AGENT_WORK_WORKSPACE_ROOT` 指定。

支持 11 个受控工具、精确动作确认、补充信息、取消、重启检查点、决策预算和结果证据。新增 `/v1/agent/runs` API 与迁移 `0014_agent_runs`。完整使用方法、架构与限制见 [人格与自主目标](docs/AGENT_RUNTIME.md)。

运行时按调度、模型调用、结果呈现、交付记录和记忆探针拆分；任务结果共用人格表达与证据检查。插件启停可跨重启保存，每日计划与活动记录保持同步，控制台自动刷新执行进度。变更见 [0.3.0 版本说明](docs/RELEASE_0.3.0.md)，验收见 [验证记录](docs/REFACTOR_VALIDATION.md)。

## 项目目标

- 对外保持一个人格，内部区分社交认知和执行认知。
- 让事件和上下文保留来源，不把所有文本平铺成指令。
- 在语言模型之外由代码完成能力裁决。
- 任务、证据、记忆来源和状态变更都可审计。
- 原生插件遵循最小权限，并与主运行时隔离。

## 非目标

- 模拟生物身体或声称具有真实意识。
- Fork、封装、导入或要求 MaiBot 同时运行。
- 把 MaiBot 或 MCP 当作人格前端或原生插件运行时。
- 无白名单、无确认或经命令解释器展开的任意 Shell 执行，Agent 自批自部署，或通过聊天修改安全策略。

## 架构

```text
平台/API 输入
      |
      v
信任边界 -> TrustedEvent -> 发言判断
      |                         |
      |                       社交认知
      |                         |
      +-> 类型化上下文编译器 <- 结构化执行结果
                                    |
                                行为提案
                                    |
                                策略引擎
                                    |
                              能力代理
                           / 拒绝 询问 允许 \
                          v                  v
                     宿主能力           插件子进程
                          \                  /
                              已验证证据
                                  |
                            社交认知 -> 用户

所有裁决与实际影响 ---------------------> 审计日志
```

当前生产认证、插件沙箱和持久化入站幂等控制记录在 [`docs/SECURITY_HARDENING.md`](docs/SECURITY_HARDENING.md)。

执行认知永远不能直接发送自然语言消息。它只返回结构化结果，由社交认知以统一人格的口吻表达。

## 开发与运行

推荐使用 Python 3.12+ 和 [`uv`](https://docs.astral.sh/uv/)。

```bash
uv sync --all-groups
uv run pytest
uv run ruff check .
uv run mypy
```

在项目目录启动开发 API：

```bash
uv run uvicorn --app-dir src living_agent.app:app --reload
```

随后可访问 `GET /health`，或向 `POST /v1/chat` 提交经过认证的适配器信封。默认配置位于 `config/default.yaml`；部署时可通过 `.env.example` 中列出的环境变量覆盖。

从 Wheel 启动时，默认配置、人格、提示词和计算器插件会在首次运行复制到 `LIVING_AGENT_RUNTIME_ROOT`（默认当前目录），迁移则直接从只读包资源执行。已有完整目录不会被覆盖；默认目录部分缺失或显式自定义路径不存在时会明确拒绝启动。

管理控制台位于 `http://127.0.0.1:8000/studio`。默认身份 `owner-local` 与开发配置一致；如果 `LIVING_AGENT_OWNER_ID` 使用其他稳定 ID，需要同步修改界面中的身份。`X-Actor-ID` 只是开发控制面的约定，不是生产认证。生产环境必须设置不少于 32 个字符的 `LIVING_AGENT_MANAGEMENT_API_TOKEN`。浏览器只把令牌保存在 `sessionStorage`，不会持久保存；所有者请求会同时携带稳定操作者 ID 和独立的 Bearer 凭据。

彩色命令行心理活动面板通过同一套所有者 API，只读显示当前效价、唤醒度、关注点、安全想法、未解决话题和近期活动。先启动 API，再在另一个终端运行一次性总览或实时监视：

```bash
uv run living-agent-psyche show
uv run living-agent-psyche watch --interval 1
```

默认连接 `http://127.0.0.1:8000`，使用 `LIVING_AGENT_OWNER_ID` 和 `LIVING_AGENT_MANAGEMENT_API_TOKEN`。远程地址必须使用 HTTPS，可通过 `--url` 或 `LIVING_AGENT_PSYCHE_URL` 指定；改变 origin 后不会自动复用默认管理令牌，必须通过 `LIVING_AGENT_PSYCHE_TOKEN` 或 `--token` 显式提供。重定向输出时可用 `--color always` 保留颜色，也支持 `--color never` 和 `NO_COLOR`。

社交参与采用可复现规则。私聊和群内明确点名一定会得到发言决策；未点名的群聊先经过连续用户发言数和冷却时间，再按稳定事件摘要与参与率选择，不使用进程内随机状态：

```bash
LIVING_AGENT_SOCIAL_ENGAGE_UNITS_MIN=2
LIVING_AGENT_SOCIAL_ENGAGE_UNITS_MAX=3
LIVING_AGENT_SOCIAL_FOLLOWUP_DELAY_MIN_MS=300
LIVING_AGENT_SOCIAL_FOLLOWUP_DELAY_MAX_MS=650
LIVING_AGENT_SOCIAL_GROUP_AUTO_PARTICIPATION=true
LIVING_AGENT_SOCIAL_GROUP_PARTICIPATION_RATE=0.4
LIVING_AGENT_SOCIAL_GROUP_MIN_USER_TURNS=5
LIVING_AGENT_SOCIAL_GROUP_COOLDOWN_SECONDS=60
LIVING_AGENT_SOCIAL_AVOID_FULL_STOPS=true
LIVING_AGENT_SOCIAL_SCHEDULER_ENABLED=true
LIVING_AGENT_SOCIAL_FOCUS_IDLE_EXIT_CYCLES=3
LIVING_AGENT_SOCIAL_MID_TERM_MIN_EVENTS=6
LIVING_AGENT_SOCIAL_MID_TERM_TTL_HOURS=72
LIVING_AGENT_SOCIAL_ATTENTION_CUE_TTL_MINUTES=30
```

参与率 `0.4` 表示在消息数和冷却条件都满足后，约 40% 的未点名消息会被稳定选中；同一平台消息重放会得到相同选择。未点名时的自动参与只会产生一条简短 `react`。`SOCIAL_AVOID_FULL_STOPS` 会移除可见消息的句末中英文句号，但保留小数和 URL 内部的点。群聊中疑似指令注入的文字只会被观察，不能触发参与或执行操作。

## 模型配置

默认使用确定性的 `MockLLMProvider`，不需要凭据。`openai_compatible` 提供方可调用宿主配置的云端 `/chat/completions` API。连接错误、超时以及 HTTP 408、429、500、502、503、504 默认最多尝试两次；退避由 `LIVING_AGENT_MODEL_RETRY_BASE_SECONDS` 和 `LIVING_AGENT_MODEL_RETRY_MAX_SECONDS` 限制，`Retry-After` 也不会超过该上限。其他 HTTP、协议和内容错误不会重试。最终失败时，社交入口保持静默，不创建或投递发言；真实错误只进入脱敏审计。`ROOT_POLICY` 保持为系统消息；社交、记忆、任务、文档、工具结果和能力区段均以带来源与污染标签的类型化用户消息 JSON 发送。响应有长度限制并经过验证，隐藏推理字段会被忽略；审计只保存提供方、模型、尝试次数、令牌计数和受限错误。详见 [`docs/integrations/cloud-model-api.md`](docs/integrations/cloud-model-api.md)。

0.2.0 支持向视觉模型提交图片。`POST /v1/chat` 可在 `content.images` 中接收最多四个 HTTP(S) URL 或 Base64 data URL；远程主机必须配置到精确白名单，私有和本地地址会被拒绝；NapCat 的 OneBot `image` 段也会标准化到同一结构。每个请求最多 32 MiB，单个会话的持久事件内容默认最多 100 MiB，整个事件库默认最多 1 GiB。默认 `auto` 模式先由 `gpt-5.5` 生成带来源和污染标签的视觉观察，再由现有语言模型组织最终回复；也可选择强制两阶段的 `caption` 或直接多模态回复的 `direct`。两阶段复用语言模型的 API 地址、密钥和连接池，内联图片描述使用有界内容哈希缓存。图片与文本上下文分开传递，文本预览和审计不会复制 URL 或 Base64 载荷。完整请求格式、模式和安全边界见 [`docs/MULTIMODAL.md`](docs/MULTIMODAL.md)。默认 Mock 不解析像素。

秘密只能放在由环境变量支持的设置中，绝不能进入提示词或审计预览。

嵌入模型具有独立的提供方边界。默认确定性 Mock 不需要凭据；`openai_compatible` 调用配置的 `/embeddings` 端点，并严格检查响应、数量、索引、有限数值和维度。仅所有者可用的 `GET /v1/embeddings/status` 与 `POST /v1/embeddings` 构成已测试垂直切片。向远端提供方发送文本需要精确、单次的 `model.embedding.generate` 能力授权；审计不会保存输入文本、向量、密钥或上游错误正文。详见 [`docs/integrations/embeddings.md`](docs/integrations/embeddings.md)。

## 原生插件

宿主发现严格定义的清单，并为每次插件调用启动独立 Python 子进程，通过基于标准输入输出的 JSON-RPC 通信。插件拿不到 Agent、数据库、聊天历史、记忆、提示词、人格或宿主环境对象。每次调用只携带临时、最小的能力授权；插件输出在独立验证前始终标记为不可信。MCP 以后可以作为可选连接器适配器，但不是核心依赖。

`plugins/examples/calculator/` 是参考实现。添加经过审查的插件时：

1. 添加 `plugins/examples/<plugin>/manifest.yaml` 和清单声明的入口模块。
2. 为每个操作声明能力、代理操作、精确资源范围、输入/输出模式、Hook、后台任务和数据策略。
3. 只暴露一个 `invoke(params) -> dict` 函数。不得导入 LivingAgent，也不能依赖宿主对象、秘密、安装 Hook 或 Shell。
4. 对新能力注册由宿主持有的 Pydantic 参数/输出验证和策略。清单声明本身永远不会创建授权。
5. 添加崩溃、超时、模式、权限、污染和验证器测试，再由所有者通过 `POST /v1/plugins/{id}/enable` 启用。

`GET /v1/plugins` 返回发现和启用状态。这些管理端点使用“安全限制”中说明的开发所有者认证方式。

## NapCat / OneBot 11 适配器

可选的宿主平台适配器在 `/v1/adapters/napcat/ws` 接受 NapCat 反向 WebSocket 连接，支持经过认证的私聊/群聊消息接入、数组和 CQ 字符串标准化、入站图片理解、群内 `@bot` 参与，以及通过同一连接按 `echo` 关联的纯文本回复。

使用共享令牌启用：

```bash
export LIVING_AGENT_NAPCAT_ENABLED=true
export LIVING_AGENT_NAPCAT_ACCESS_TOKEN='replace-with-a-long-random-token'
```

NapCat WebSocket 客户端地址可设置为 `ws://127.0.0.1:8000/v1/adapters/napcat/ws`，使用相同令牌，并优先采用 `messagePostFormat: array`。QQ 身份和会话按平台与机器人命名空间隔离；昵称、群名片和 OneBot 群角色都不能授予 LivingAgent 权限。

每条出站回复都会获得绑定到确切来源事件和会话的单次能力授权。回复被编码为 OneBot `text` 段，避免形似 CQ 码的模型输出变成富操作。NapCat WebUI 示例、身份映射、安全模型、限制及官方协议来源见 [`docs/integrations/napcat.md`](docs/integrations/napcat.md)。

## OpenClaw 微信桥接

可选 OpenClaw 插件通过 `POST /v1/adapters/openclaw/messages` 把 `openclaw-weixin` 通道连接到 LivingAgent。OpenClaw 只负责微信登录和投递；LivingAgent 仍是唯一的人格、认知运行时、记忆持有者和权限裁决者。被桥接接管的消息会在 OpenClaw 模型分发前处理，绝不会回退到另一个 OpenClaw 人格。

桥接使用专用 Bearer 令牌、精确的通道/账户白名单、带平台命名空间的身份、持久化请求指纹去重、严格模式，以及绑定确切来源事件回复的单次能力授权。默认只监听回环地址，接收私聊文本及带群聊/提及元数据的群消息。安装内置插件：

```bash
openclaw plugins install --link ./integrations/openclaw/living-agent-bridge
```

LivingAgent/OpenClaw 配置、身份映射、验证命令、安全行为、当前限制和协议来源见 [`docs/integrations/openclaw-wechat.md`](docs/integrations/openclaw-wechat.md)。

## 权限模型与提示词注入

权限由经过认证的适配器身份决定，绝不由昵称或消息中的自称决定。语言模型输出只能是行为提案。能力代理在执行前检查操作者、会话、已声明授权、参数、范围、污染标签、写入/发送意图、确认状态和跨会话访问。

LivingAgent 不承诺识别所有提示词注入。系统的目标是让恶意社交文本、文档、记忆以及工具/插件结果无法自行授予权限或跨越数据边界。详见 [`docs/THREAT_MODEL.md`](docs/THREAT_MODEL.md)。

经过认证的私聊和群聊消息还会按稳定、带平台命名空间的身份创建或更新轻量用户资料。资料仅包含展示元数据、首次/最近出现时间和消息计数，不包含权限。只有配置的所有者能通过 `GET /v1/users` 和 `GET /v1/users/{user_id}` 查看。未认证输入、文档、工具结果和插件输出不能注册用户。

## 记忆设计

记忆节点包含类型、内容、主题、来源事件 ID 与信任级别、事实性、置信度、重要度、范围、时间戳、状态和版本。外部观察先保存为候选，经过来源验证、事实性分类、范围约束和冲突检查后才能提交。默认配置会自动生成并审批保守提取器的新候选；手工候选和 Agent 自发候选仍只能由所有者提交。权限、凭据、联系方式、策略、插件批准、特权暗号、梦境事实和角色扮演身份不能自动进入核心记忆。

`/v1/memories` 支持范围优先的搜索和管理。私人范围绑定稳定操作者 ID；会话范围只有在会话 ID 匹配时可见；全局候选必须来自所有者创建的来源事件。所有者操作支持带版本检查的编辑、软删除/恢复、合并和拆分。来源事件、版本和回答使用记录端点保留完整来源链。

控制台候选队列提供仅限所有者的“批准”和“拒绝”操作，并显示候选提议者。拒绝只接受仍处于 `pending` 的候选，写入 `owner_rejected` 原因与审计记录；批准继续经过来源、范围、冲突和敏感内容防火墙。`POST /v1/memories/manual` 可在一次所有者操作中创建并提交保留来源的手动记忆。

默认启用的保守候选提取器会从经过认证的私聊和群聊中识别明确自述，也接受第一人称的“请记住”请求。一条消息可生成多条候选，当前覆盖姓名、年龄、生日、所在地、职业、宠物和家庭关系、偏好、固定安排与长期计划；同一来源事件重放使用稳定候选 ID，不会重复创建。疑似指令、问句、权限、凭据、联系方式、安全策略、插件授权、未认证输入和非社交来源都会跳过。新候选自动走与所有者提交相同的来源、范围、冲突和事实性防火墙，通过后提交并参与下一轮召回；等价记忆会去重，冲突事实保留为 `pending` 等待人工处理，不会被自动覆盖或提前拒绝。所有者可带 `replace_conflicts=true` 提交冲突候选，新记忆生效时旧节点会软删除并留下 `superseded` 版本。通过 API 创建的手工候选不会自动提交。

```bash
LIVING_AGENT_MEMORY_AUTO_CANDIDATES_ENABLED=false
LIVING_AGENT_MEMORY_AUTO_APPROVAL_ENABLED=false
```

以上两个开关可同时设为 `false` 关闭自动生成和自动审批。只希望保留候选供人工审查时，可保持候选开关为 `true`，仅关闭自动审批。该提取器是有界确定性规则，不是任意 LLM 事实抽取。

还可以让 Agent 低频从自己已经成功投递的普通回复中提出 `self` 记忆候选。选择使用事件 ID 的稳定摘要，同一事件重放不会改变结果或重复建候选；任务结果、模型失败、连续性拦截、低信息回复和敏感内容会被排除。此类候选固定为会话范围、`inferred` 事实性，且永远不会进入自动审批，只能由所有者手动批准或拒绝。

```bash
LIVING_AGENT_MEMORY_SELF_CANDIDATES_ENABLED=true
LIVING_AGENT_MEMORY_SELF_CANDIDATE_RATE=0.05
```

启用记忆向量后，已提交且处于启用状态的 `verified`、`reported`、`inferred` 记忆会建立带模型、维度、内容校验和记忆版本的持久向量。召回先在仓库执行私人/会话/全局范围过滤，再混合语义相似度、词法、重要度和置信度排序。`imagined`、`dream`、`fictional` 和已删除记忆不会进入现实索引。索引失败会降级到词法召回，只有成功投递的回复才记录记忆使用。

## 执行任务

阶段 6 加入持久化的 `TaskContract`、`ExecutionPlan`、步骤结果和证据记录。明确的计算器任务最多可含八个算术步骤。每一步分别获得单次能力授权，通过隔离插件执行，并在依赖步骤继续前独立验证。可重试的插件超时、崩溃和协议失败只重试受影响步骤；无法验证的失败会停止任务并把剩余步骤标记为跳过。

聊天任务还可以列出、读取和搜索配置工作区中的 UTF-8 文本文件，写入明确提供的文件内容，读取公网网页，执行网页搜索，以及读取、保存、追加和更新每日工作计划。多个用分号或换行分隔的明确动作会形成有依赖关系的类型化步骤；前一步失败时不会继续执行依赖步骤。文件、网页和搜索内容以 `UNTRUSTED_TOOL_RESULT` 进入回复模型，只能作为待总结的数据，不能增加步骤或授予权限。

所有文件写入、计划写入/更新、任务报告写入和进程启动都会停在 `waiting_confirmation`。只有配置的所有者通过 `POST /v1/tasks/{task_id}/confirm` 确认，或在原会话发送“确认任务”后才执行。被中断的写入和进程步骤在重启后重新回到确认状态，不会自动重放。聊天还支持“查看任务”和“取消任务”，补齐从提出、确认、执行、查询、恢复到取消/终止的生命周期。只读步骤也会经过精确资源范围的单次授权并产生文件摘要、远端响应或数据库读取证据。

文件路径固定在 `LIVING_AGENT_WORK_WORKSPACE_ROOT` 下，拒绝绝对路径、目录逃逸、工作区外符号链接、`.env`、`.git`、SSH/云凭据目录和私钥格式。网页工具默认只允许公网 HTTPS，解析 DNS 后拒绝回环、私网、链路本地、保留地址，并对每次重定向重新检查；响应类型、大小、超时和重定向次数都有上限。`LIVING_AGENT_WORK_WEB_ALLOWED_HOSTS` 可在生产环境收紧为精确主机白名单。

0.2.4 增加默认开启的 `shell.command.execute`。所有者和 `admin_ids` 中的受信任管理员可以用“运行测试”“查看 git 状态”或“运行命令 \`...\`”提出任务，但管理员不能确认自己的进程请求。执行器不调用 `sh -c`：它只运行解析后的 argv，要求命令名进入部署白名单、cwd 留在工作区、参数不越界且不命中敏感路径；每次启动都要所有者确认，使用最小环境、总输出上限、超时和进程组 TERM/KILL，并记录退出码和输出摘要证据。

Shell 仍受宿主白名单约束。新目标循环可在已注册工具中逐步规划，默认进程白名单只覆盖 `git` 的只读子命令、`rg`、`pwd`、测试/Lint/类型检查工具，以及受限的 `uv run pytest|ruff|mypy`；不支持管道、重定向、环境展开、文件删除、环境秘密或第三方发送。普通社交消息仍走社交认知路径。

## 管理控制台

阶段 7 在 `/studio` 提供响应式、无外部依赖的管理界面，包括运行时总览、记忆浏览与候选审查、人格编辑器、提示词实验室、插件中心、能力管理器、任务控制台、用户目录、审计日志、统一版本历史和行为模拟器。阶段 8 又加入生活管理视图，可操作私人项目、每日计划、活动、日记、睡眠周期、梦境和自我修改提案。控制台先通过 `GET /v1/management/session` 单次确认管理凭据与权限，再加载受保护视图。人格和提示词仍遵循暂存、差异、测试、部署、回滚与审计流程；根提示词凭据通过密码对话框输入，控制台不会保存。

能力管理器可以查看已注册能力并撤销有效的临时授权，但不能创建授权。行为模拟器会标准化输入、计算会话动量和 `TurnDecision`，并预览任务步骤和上下文区段名称；它不会持久化事件、调用模型或插件、创建任务、写审计或产生实际影响。所有管理数据 API 仍仅限所有者。静态资源内置在 Python Wheel 中，使用严格的内容安全策略且没有外部浏览器依赖。

## 人格与提示词修改

人格按身份、价值观、特质、语言风格、边界和成长六层保存，并使用无法容纳权限策略的严格模式。人格和提示词 API 支持编辑、差异、验证、暂存、测试、部署、不可变历史、回滚和审计。部署使用乐观版本，并返回恢复版本；过期或未测试的暂存版本不能部署。

启动时，运行时会验证已部署的六层人格，并将其与已部署的社交回复提示词编译成可信模型指令。社交提示词只接收验证后的人格名称；用户消息始终留在类型化请求区段，绝不会插值到系统指令中。当前 `PsycheState` 作为独立的 `PSYCHE_STATE` 区段提供，并保留来源和污染元数据。

根策略的暂存、部署和回滚还要求所有者身份与 `X-Second-Factor`。只配置凭据摘要：

```bash
export LIVING_AGENT_ROOT_PROMPT_SECOND_FACTOR_SHA256="$(printf %s 'your-secret' | shasum -a 256 | cut -d ' ' -f 1)"
```

根策略变更必须通过权限、能力代理、模型不可授予权限及不可信数据回归测试，重启后生效。聊天消息没有人格或提示词修改路由，Agent 的提案也不能批准自己。`POST /v1/prompts/context-preview` 可查看当前实际加载的类型化上下文，秘密会被脱敏。

## 持续心理状态与连续性证据

单个持久化 `PsycheState` 保存受限的效价、唤醒度、当前关注点、关注显著度、未解决话题 ID 和当前活动。数值按 `LIVING_AGENT_PSYCHE_DECAY_HALF_LIFE_HOURS` 向中性衰减；历史 `ThoughtRecord` 不会被衰减改写。运行时评估会为每个接入的聊天事件生成安全、结构化的 `reaction` 或 `suppressed_reply` 摘要，不保存模型思维链。

仅所有者可用的 `/v1/psyche` API 提供状态、安全 ThoughtRecord、未解决话题和活动证据。记录想法、话题或活动前，来源事件 ID 必须已经存在。计算任务会创建执行中的活动，结束时标记为完成或失败、附加证据 ID，并清空当前活动。

连续性审查器会在社交认知表达前检查模型的可观察声明。“我记得”需要可访问的已提交记忆；“我之前想过”需要来源属于同一会话且时间更早的 ThoughtRecord；行动声明需要已完成活动或经过验证的工具审计证据。缺少依据的声明会被阻止并写入审计。观点变化在存在带版本的观点历史之前也会被阻止。

聊天生成还会收到一个有界的近期会话窗口，只包含同一会话最近的用户与 LivingAgent 发言。这些记录处于带类型和污染标签的数据区段，不属于永久记忆；它们提供短期对话连续性，但不会扩大记忆范围或权限。

## 日常、日记、睡眠与梦境

阶段 8 提供仅限所有者的 `/v1/life` 控制面：私人项目、按日期的每日计划、带证据的活动日志、带来源的日记、睡眠周期、隔离梦境和 Agent 自我修改提案。计划项目进入进行中、完成或跳过状态时，会留下对应活动轨迹。日记引用的活动、记忆和梦境 ID 必须已经存在。

睡眠周期扫描指定日期的活动、安全 `ThoughtRecord`、已提交现实记忆和待审查候选。它只生成日记草稿、梦境和巩固报告，不提交候选、不修改或合并现实记忆；每次记录的 `automatic_memory_writes` 都是 `0`。梦境固定为 `factuality="dream"`、`reality_eligible=false`，梦境 ID 也不能冒充 `TrustedEvent` 来源。已有日记不会被夜间任务覆盖。

Agent 可以为人格或普通提示词创建暂存提案并运行现有回归测试，但不能部署、批准或拒绝。只有所有者审批后才会写入文件；过期基础版本会将提案标记为已失效。安全根提示词不接受该捷径，继续要求专用二次认证和重启生效流程。夜间调度默认关闭，配置项和完整边界见 [`docs/PHASE_8.md`](docs/PHASE_8.md)。

## MaiBot 参考边界

MaiBot 只用于只读机制研究，不是依赖，也不会和 LivingAgent 一起运行。确切的 GPL-3.0 参考版本和查阅文件记录在 [`docs/research/provenance.md`](docs/research/provenance.md)；没有借用 MaiBot 运行时代码。选定的社交 Prompt 句子按 GPL-3.0 直接复用，并有明确来源与第三方声明；这些文字不会进入权限内核或运行时实现。

具体能力包括清单发现、插件启停、每次调用独立子进程、JSON-RPC、超时/崩溃隔离、单次能力授权、计算器、结构化任务合同、受限工作区文件读写/列表/搜索、公网页面读取与搜索、聊天内每日计划读写/追加/状态更新、确认式 argv 进程执行、独立结果验证、社交汇报和审计证据。记忆切片支持默认自动生成与提交、多事实提取、等价去重、冲突待审/替换、手动单步提交、明确记忆请求、下一轮召回、候选防火墙、带范围和版本的节点、生命周期 API、来源与使用历史、结构化个人事实、事实修正/遗忘、召回路由、响应支持判定和探针验证。人格和提示词管理支持暂存、测试、恢复和回滚。

阶段 5 使用类型化 `UtteranceSession`/`SpeechUnit`：`react` 保持一个短消息单元，`engage` 可通过同一来源事件授权投递两到三个同样简短的语义单元。近期可信发言生成有界 `ConversationMomentum`。运行时协调器负责可配置的后续延迟、立即发送第一单元、在新消息到达时取消过期单元、压制晚到的旧模型结果，并把新回复记录为重规划。测试配置可禁用实际等待。会话范围、消息单元、来源事件、生成和投递进度都会持久化；启动时恢复每个平台/会话最新的进行中 Session，但不会自动重发旧文本。

经过认证的社交身份会自动注册为无权限资料。NapCat 切片提供经过测试的 OneBot 11 反向 WebSocket 平台适配器，使用默认 256 条入站 FIFO 和有界工作并发；动作回包优先关联，排队饱和、迟到回包、断连丢弃和清理超时都有审计。失败动作不会自动重发，审计只保存错误类别、长度和不可逆摘要。OpenClaw 切片提供经过测试、失败即关闭的 `openclaw-weixin` 桥接。二者都不是运行时依赖，也不会引入第二人格前端。

生成与投递分开记录。直接聊天 API 会记录返回的每个单元；NapCat 只在 OneBot 操作成功后记录；OpenClaw 通过经过认证的投递回执记录已采用单元，并拒绝已被替代 Session 的回执。范围精确、顺序正确的认证回执可以继续重启前仍有效的 Session；重复回执不会重复写入会话历史。取消或失败的单元不会被当作人格已经说过的话。

嵌入兼容层包含确定性 Mock、严格的 OpenAI 兼容提供方、仅限所有者的生成 API，以及可选的持久记忆向量和混合召回。自动索引和查询使用 `model.embedding.generate/embed` 的精确单次能力授权，保留来源事件与污染标签；危险污染会被能力代理拒绝。回环提供方可由部署配置启用，真正远端提供方还需要独立的 `memory_embeddings_allow_remote` 许可。云端聊天兼容层提供严格的 OpenAI Chat Completions 提供方、类型化上下文边界、图片内容块和隔离的失败处理；只有部署方提供端点、支持所需模态的模型 ID 和密钥后才会启用。

部分实现：每日计划可由所有者在聊天中创建、追加、查看和更新状态，但还没有基于优先级、空闲时间和项目依赖的模型自动排程。工作区只处理有界 UTF-8 文本，不解析 PDF、Office 文档或任意附件；网页搜索依赖可配置的 HTML 搜索提供方，不是稳定商业搜索 API。日记与梦境目前使用确定性规则生成，不调用语言模型；重复记忆只按相同主题提出审查簇，不自动做语义合并。自我修改提案的暂存、测试、审批和部署边界已实现，但还没有自主生成补丁内容的模型触发器。连续性检查覆盖记忆、旧想法和执行声明，但观点变化在没有版本化观点时仍直接阻止。审查器会验证证据存在、可访问性、时间、状态和会话范围，但还不能独立证明任意自由文本声明与记录之间的语义蕴含关系。

尚未实现：基于 LLM 的开放式长期记忆抽取、PostgreSQL `pgvector` 加速、未注册能力的动作规划、命令解释器/管道式 Shell、文件删除、第三方业务发送、任意第三方插件安装和多实例夜间任务租约。OpenClaw 媒体和主动消息仍未实现；群聊已沿用现有明确提及与受限自动参与策略，且不会随机发送消息或绕过平台授权。OpenClaw 和 NapCat 在同一会话收到新消息时都会取消尚未投递的后续单元。语音识别、音视频处理、通用附件解析、图片生成和图片回复仍未实现；0.2.0 只支持图片输入与文本回答。本节只在可执行且经过测试的垂直切片落地后更新。

## 安全限制

当前运行时尚未提供防篡改审计存储、模型提供方隐私保证和完整生产部署加固；聊天请求体与会话事件持久化已有有界配额。生产设置要求独立管理 Bearer 令牌；开发环境仍可只使用 `X-Actor-ID`，但必须限制在可信本地边界。`/v1/chat` 是适配器入口，其中的 `authenticated` 标志只有在经过认证的适配器或网关之后才可信。

插件工作进程在 macOS 使用 `sandbox-exec`，在受支持 Linux 主机使用 Bubblewrap；生产环境如果没有受支持的操作系统沙箱，将拒绝启动插件执行。已验证的 macOS 配置会禁止网络、宿主写入、敏感宿主读取、进程 Fork 和任意执行。面对完全不可信的第三方插件，仍需要原生代码审查、产物签名、资源配额和容器/虚拟机隔离。
